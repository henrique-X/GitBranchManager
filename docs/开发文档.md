## 1. 项目概述

### 1.1 项目定位
一款 **Windows 10/11 单机桌面端** 的 Git 分支管理工具，分支查询/删除通过 GitLab / GitHub / Gitee 的开放 API 直接管理远程仓库；**批量创建分支基于本地仓库执行**（本地建分支，push 由用户自行完成）。列表与删除**无需本地 clone**。

### 1.2 核心价值
| 痛点 | 解决方案 |
|---|---|
| 多平台切换管理分支繁琐 | 一个桌面工具统一管理 GitHub / Gitee / GitLab |
| 批量删分支靠命令行逐条执行 | 多选 + 二次确认 + 批量删除，失败原因可视化 |
| 批量建分支命名易错、重复劳动 | 命名模板 + 变量填充 + 基于多源分支批量创建本地分支 |
| 本地多项目散落在各目录 | 工作区根目录 + 多级扫描（默认 3 层），自动识别全部 Git 项目并与远程仓库匹配 |

### 1.3 范围约束
- 仅支持 Windows 10 / 11，单机使用（自用，不对外发布）
- 不需要服务端、不做多人共享
- 本机需已安装 **Git for Windows**（已确认已安装）
- 本期不含 PR / 合并 / Tag 管理（架构上预留扩展）
- 工具**不代为 push**，创建分支后由用户自行 push

## 2. 技术选型（与 cc-switch 同栈，可行）

| 层 | 技术 | 说明 |
|---|---|---|
| 桌面框架 | **Tauri 2** | 体积小、内存占用低，官方支持 Windows 10/11 |
| 后端 | **Rust** | 调用平台 API、执行本地 Git、本地存储、加密凭据 |
| 前端 | **React + TypeScript + Vite** | cc-switch 同款组合，生态成熟 |
| UI | **Tailwind CSS + shadcn/ui** | 快速构建桌面风格界面 |
| 本地存储 | **SQLite**（rusqlite） | 账号、模板、默认值、本地项目映射 |
| 凭据加密 | **Windows 凭据管理器**（keyring crate） | PAT 加密保存 |
| 本地 Git | **系统 Git（Git for Windows）** | fetch / pull / 创建本地分支，通过子进程调用 |
| 自动更新 | **tauri-plugin-updater** | Windows 无感更新，免卸载重装 |

### 2.1 自动更新方案（已确认）
- 更新文件托管在 **GitHub Releases**
- **不购买 Windows 代码签名证书**（Authenticode）；自用可接受 SmartScreen 首次运行提示
- Tauri updater 仍需使用**自带的更新签名密钥**（`tauri signer generate`，免费生成），用于校验更新包完整性、防劫持——这与"不买代码签名证书"不冲突，属于免费的自签名机制
- 结论：满足"自动更新、无需卸载重装"，无额外费用

│      ▼              ▼               ▼          ▼  │

│ │ 平台 API    │ │ 本地 Git   │ │ SQLite   │ │ Windows  │
│ │ 适配层      │ │ 服务       │ │ 本地配置库│ │ 凭据管理器│

│ └──────┬─────┘ └─────┬──────┘

### 3.1 模块划分
| 模块 | 职责 |
|---|---|
| 账号管理 | 平台账号增删改、PAT 保存、连接测试、切换当前账号 |
| 仓库浏览 | 拉取当前账号名下仓库（含组织/群组）、搜索过滤、分页 |
| 本地项目管理 | 工作区配置、多级扫描（默认 3 层）、本地项目与远程仓库匹配 |
| 分支管理 | 分支列表展示、保护分支标识 |
| 分支删除 | 单仓库内多选删除、二次确认、结果与失败原因（走平台 API） |
| 模板管理 | 命名模板 CRUD、变量定义、默认值配置 |
| 批量创建 | 选源分支 → 填参数 → 预览（本地+远程同名检测）→ fetch/pull + 创建本地分支（不 push） |
| 设置与更新 | 偏好设置、更新检查、关于页 |

### 3.2 平台适配器设计
统一抽象 `PlatformProvider` 接口（Rust trait）：
- `current_user()` 当前登录用户
- `list_repos()` 仓库列表（**含组织/群组仓库**，分页）
- `list_branches(repo)` 分支列表
- `is_branch_protected(repo, branch)` 保护分支检测
- `delete_branch(repo, branch)` 删除分支

三个平台各自实现，新增平台（未来）只需新增适配器，UI 不变。
**注意：批量创建分支不经过平台适配器，由本地 Git 服务执行。**

**组织/群组仓库拉取方式**
- GitHub：`GET /user/repos`（affiliation 含 organization_member）
- GitLab：`GET /projects?membership=true`（含群组项目）
- Gitee：`GET /user/repos`（个人）+ `GET /user/orgs` 枚举所属组织 + 逐组织 `GET /orgs/{org}/repos`（适配器内部合并去重）

### 3.3 本地 Git 服务设计（Rust）
- 通过子进程调用系统 `git` 命令（不引入 libgit2，规避复杂边界）
- 核心操作：
  - `scan_workspace(root, depth)` 扫描工作区内的 Git 仓库（默认深度 3）
  - `repo_status(path)` 检查未提交改动、当前分支
  - `fetch_pull(path, branch)` 更新源分支（fetch + pull）
  - `create_branch(path, source, target)` 先将本地源分支快进到远程（分叉时按本地创建并提示），再基于本地源分支创建本地分支（不 push；本地无源分支时基于远程源分支）
- 依赖本机 Git 凭据管理器完成 fetch/pull 认证；工具本身**不执行 push**

## 4. 功能需求详述（冻结）

### 4.1 账号管理（P0）
- 支持三类平台：GitHub（公网）、Gitee（公网）、GitLab（**支持自建私有部署，可配置 baseURL**）
- 认证方式统一：**仅 PAT（私人令牌）**，不支持密码登录
- 支持同时配置**多个账号**（如同时登录 GitHub + Gitee + GitLab），侧边栏可切换当前账号
- PAT 使用 Windows 凭据管理器加密存储，数据库中只存引用键，**明文不落盘**
- 添加账号后自动调用"当前用户"接口验证并回显用户名 / 头像
- 支持编辑、删除账号；删除账号需确认，且同步清除凭据管理器中的 PAT

### 4.2 仓库列表（P0）
- 拉取当前账号名下所有仓库，**包含所属组织 / 群组的仓库**（已确认）
- 展示字段：仓库名、所属平台、来源（个人/组织/群组）、可见性（公开/私有）、默认分支、最近更新时间
- 支持关键词搜索、按平台/来源过滤、分页加载
- 点击仓库进入分支管理页

### 4.3 本地项目管理（P0）
**工作区配置**
- 支持配置一个或多个**工作区根目录**（例如 `D:\work\fe`）
- 对工作区进行**多级扫描**，识别其中所有独立 Git 仓库（以子目录存在 `.git` 为准）
- **扫描深度默认 3 层**（已确认），设置中可调整

**项目识别与匹配**
- 扫描结果列表展示：项目名（目录名）、本地路径、远程仓库地址（origin）
- 自动按 remote URL 与平台拉取的仓库**匹配关联**；匹配不上的支持手动关联
- 一个远程仓库只关联一个本地路径；同一本地路径只对应一个远程仓库
- 支持手动刷新扫描、移除工作区、移除单个项目关联

**约束**
- monorepo（一个 `.git` 管理多个子项目）按**整个仓库**识别为一个项目，分支操作针对整个仓库
- 未关联本地路径的仓库，在批量创建时**阻断并提示"请先配置本地路径"**（不提供 clone、不降级 API 创建——已确认）

### 4.4 分支列表与批量删除（P0）
**分支列表**
- 展示：分支名、最后提交信息（hash + message + 作者 + 时间）、是否保护分支
- 保护分支显示 🔒 标识，**不可勾选删除**
- **保护分支识别失败时（如 Gitee 无法识别）：同样不可删**，置灰并提示"无法识别，请到平台网页确认"（已确认：不允许兜底删除）

**批量删除（单仓库内，走平台 API，不依赖本地仓库）**
- 支持多选分支 → 点击删除 → 弹出二次确认框（列出待删分支清单）
- 确认后批量调用删除 API，逐条展示结果：
  - 成功 / 失败
  - 失败原因（权限不足 / 分支不存在 / 平台限制等，展示平台返回的原始信息）
- 删除过程可中断；完成后刷新分支列表

### 4.5 命名模板与批量创建本地分支（P0，核心功能）

**命名模板管理**
- 模板支持**自定义并保存多套**，增删改查
- 内置变量：`{userName}`、`{projectName}`、`{TG_ID}`、`{sourceBranch}`
- 支持用户**自定义新增变量**（如 `{env}`、`{version}`）
- 模板示例：`{userName}/{projectName}_TG-{TG_ID}/{sourceBranch}`

**变量取值规则**
- 所有变量值**运行时手动输入**
- 可为"当前仓库"配置每个变量的**默认值**，创建时一键套用默认值（也可临时修改）
- 默认值按仓库分别保存

**批量创建流程（本地创建，不 push）**
1. **前置条件**：该仓库已关联本地路径；未关联时阻断并提示"请先配置本地路径"
2. 在分支列表中**勾选一个或多个源分支**（如 `dev`、`sit`）
3. 选择命名模板 → 填写 / 套用变量值
4. 系统生成目标分支清单：**每个选中源分支 × 每组参数值**，逐条预览
   - 例：模板 `{userName}/{projectName}_TG-{TG_ID}/{sourceBranch}`
   - 源分支 `dev` + `TG_ID=1024` → `zhangsan/myrepo_TG-1024/dev`
   - 源分支 `sit` + `TG_ID=1024` → `zhangsan/myrepo_TG-1024/sit`
5. 预览页冲突检测（已确认策略）：
   - **本地已存在同名分支** → 该条标红**阻止**
   - **远程已存在同名分支** → 该条标黄**提示**（不阻止，由用户决定是否继续）
6. 确认后执行创建：
   - 自动 **fetch / pull** 更新源分支（自动执行，无需用户操作）
   - 若本地存在**未提交改动** → **阻断并提示用户先处理**（stash / commit 由用户自行决定，工具不代劳）
   - 通过本地 Git **创建本地分支**（基于**本地源分支**；本地源分支先尝试快进到远程，与远程分叉时按本地创建并在结果中提示）
   - **不执行 push**；完成后展示已创建分支清单，由用户自行 push
7. 逐条展示创建结果：成功 / 失败及失败原因（如 fetch 失败、冲突、Git 报错信息）

**命名合法性校验**
- 按平台规则校验分支名（非法字符、长度、是否 `HEAD` 等保留名）
- 不合法的目标分支在预览阶段标红，阻止提交

### 4.6 设置（P1）
- 自动更新开关 + 手动检查更新 + 当前版本号
- 工作区管理与扫描深度配置（默认 3 层）
- 清除本地数据（账号、模板、默认值、本地项目映射）
- 界面语言：中文（架构预留 i18n 扩展）

## 5. 平台 API 与本地 Git 职责划分

| 能力 | 执行方式 | 说明 |
|---|---|---|
| 当前用户 / 仓库列表 / 分支列表 / 保护分支检测 / 删除分支 | 平台 API | 无需本地仓库 |
| 创建分支 | **本地 Git** | fetch/pull 源分支 → 本地建分支 → 不 push |

**平台 API 映射（查询与删除）**

| 能力 | GitHub（api.github.com） | Gitee（gitee.com/api/v5） | GitLab（自建域名 /api/v4） |
|---|---|---|---|
| 认证头 | `Authorization: Bearer <PAT>` | `access_token` 参数 | `PRIVATE-TOKEN: <PAT>` |
| 当前用户 | `GET /user` | `GET /v5/user` | `GET /user` |
| 仓库列表（含组织） | `GET /user/repos`（affiliation 含 organization_member） | `GET /user/repos` + `GET /user/orgs` + 逐组织 repos，合并去重 | `GET /projects?membership=true` |
| 分支列表 | `GET /repos/{o}/{r}/branches` | `GET /v5/repos/{o}/{r}/branches` | `GET /projects/:id/repository/branches` |
| 保护分支检测 | 列表接口自带 `protected` 字段 | ⚠️ 需开发期验证；**无法识别时不可删** | `GET /projects/:id/protected_branches` |
| 删除分支 | `DELETE /repos/{o}/{r}/git/refs/heads/{b}` | `DELETE /v5/repos/{o}/{r}/branches/{b}` | `DELETE /projects/:id/repository/branches/:b` |

**速率限制（开发时需处理退避与提示）**
- GitHub：PAT 5000 次/小时
- Gitee：有每日/每分钟限额，需实测
- GitLab 自建：取决于服务端配置

**本地 Git 依赖**
- fetch / pull 认证依赖本机 Git 凭据管理器（已 clone 过的仓库通常已配置好）
- 工具不存储、不使用 PAT 执行 push（push 由用户自行完成）

## 6. 本地数据模型（SQLite）

```sql
-- 工作区表
CREATE TABLE workspace (
  id INTEGER PRIMARY KEY,
  root_path TEXT NOT NULL UNIQUE,   -- 工作区根目录（如 D:\work\fe）
  scan_depth INTEGER NOT NULL DEFAULT 3,
  created_at TEXT
);

-- 本地项目表（扫描结果 + 与远程仓库的匹配）
CREATE TABLE local_project (
  id INTEGER PRIMARY KEY,
  workspace_id INTEGER NOT NULL REFERENCES workspace(id),
  name TEXT NOT NULL,               -- 项目名（目录名）
  local_path TEXT NOT NULL UNIQUE,  -- 本地仓库绝对路径
  remote_url TEXT,                  -- origin 远程地址
  repo_platform TEXT,               -- 匹配到的平台（github|gitee|gitlab，可空）
  repo_id TEXT,                     -- 匹配到的平台仓库 ID（可空）
  matched_at TEXT,                  -- 匹配时间（可空 = 未匹配）
  UNIQUE(workspace_id, local_path)
);

-- 账号表（PAT 明文不存库，存凭据管理器引用键）
CREATE TABLE account (
  id INTEGER PRIMARY KEY,
  platform TEXT NOT NULL,        -- github | gitee | gitlab
  label TEXT NOT NULL,           -- 用户可读别名
  base_url TEXT,                 -- GitLab 自建地址；官方平台为 NULL
  api_username TEXT,             -- 验证后回填的平台用户名
  avatar_url TEXT,
  credential_key TEXT NOT NULL,  -- Windows 凭据管理器键名
  created_at TEXT,
  last_used_at TEXT
);

-- 命名模板表
CREATE TABLE naming_template (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,            -- 模板名（如"测试环境分支"）
  pattern TEXT NOT NULL,         -- 如 {userName}/{projectName}_TG-{TG_ID}/{sourceBranch}
  variables TEXT NOT NULL,       -- JSON: 变量定义列表（内置+自定义）
  created_at TEXT,
  updated_at TEXT
);

-- 仓库级默认值表
CREATE TABLE repo_variable_default (
  id INTEGER PRIMARY KEY,
  repo_platform TEXT NOT NULL,
  repo_id TEXT NOT NULL,         -- 平台仓库唯一标识
  template_id INTEGER NOT NULL,
  values TEXT NOT NULL,          -- JSON: {变量名: 默认值}
  updated_at TEXT,
  UNIQUE(repo_platform, repo_id, template_id)
);

-- 设置表（key-value）
CREATE TABLE app_setting (
  key TEXT PRIMARY KEY,
  value TEXT
);
```

**Windows 凭据管理器**
- 键名规则：`GitBranchManager/{platform}/{account_id}`
- 值：PAT 明文（由系统 DPAPI 保护，仅当前 Windows 用户可读）

## 7. 安全设计

| 风险 | 措施 |
|---|---|
| PAT 泄露 | 仅存 Windows 凭据管理器（DPAPI 加密），日志与界面均脱敏 |
| 误删分支 | 删除必须二次确认；保护分支禁止删除；**保护分支无法识别时同样禁止删除**；结果面板可审计 |
| 本地未提交改动被覆盖 | 创建前强制检查，发现未提交改动立即阻断，**不做 stash / reset 等破坏性操作** |
| 更新包被劫持 | updater 使用免费自签名密钥校验（托管 GitHub Releases，无 Authenticode 证书，自用接受 SmartScreen 提示） |
| API 令牌权限过大 | 文档引导用户按平台"最小权限"创建 PAT（只勾 repo/branch 相关权限） |
| 自建 GitLab 证书 | 默认校验 HTTPS 证书；可在账号设置中显式开启"跳过证书校验"并标红警示（仅自建） |
| 本地仓库凭据 | fetch/pull 依赖本机 Git 凭据管理器，工具不读取、不存储 Git 凭据 |

## 8. 非功能需求

- **性能**：仓库 / 分支列表分页加载（每页 50-100）；API 批量删除并发度 ≤ 5；工作区多级扫描（默认 3 层）异步执行并显示进度；本地创建分支逐条反馈
- **可靠性**：所有 API 调用有超时（10s）与错误分类提示；批量操作逐条反馈，单条失败不中断整批；本地 Git 失败时展示 git 原始报错
- **可用性**：全中文界面；关键操作有确认与强提示（删除不可撤销；未提交改动阻断说明清晰）
- **可维护性**：平台适配器与本地 Git 服务隔离；UI 与业务逻辑分层；预留 PR / Tag / 合并模块扩展点

## 9. 风险清单

| # | 风险 | 影响 | 应对 |
|---|---|---|---|

## 11. 验收标准（冻结）

- 三平台账号可添加、验证、切换；PAT 加密存储，数据库文件中不可见明文
- 任一账号可拉取仓库列表（含组织/群组仓库）并进入分支列表，数据与平台网页一致
- 工作区配置后可按默认 3 层深度扫描出全部 Git 项目，并按 remote URL 与平台仓库自动匹配
- 单仓库内多选删除：保护分支不可删（含识别失败场景）；删除有二次确认；失败原因可见
- 批量创建：仓库未关联本地路径时阻断提示；自动 fetch/pull；未提交改动阻断；本地同名分支标红阻止、远程同名分支标黄提示；多源分支 × 多参数组生成清单正确；本地创建基于**本地源分支**（创建前已快进更新，分叉时有提示）且**不执行 push**；结果明细准确
- 自动更新：检测新版本 → 从 GitHub Releases 下载 → 自签名校验 → 安装重启，全程无需卸载重装
