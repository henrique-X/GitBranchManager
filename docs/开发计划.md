## 2. 各阶段任务分解

### M1 工程骨架 + 账号管理（5 天）
- [ ] Tauri 2 + React + TS + Vite + Tailwind 工程初始化；CI 脚本
- [ ] SQLite 建表 + 迁移机制；Windows 凭据管理器封装
- [ ] 平台适配器接口（trait）定义 + GitHub / Gitee / GitLab 三实现
- [ ] 本地 Git 服务骨架：系统 git 子进程封装、git 可用性检测、错误分类
- [ ] 账号管理页：添加账号（平台选择、baseURL、PAT）、连接测试、账号列表、切换当前账号、删除账号
- [ ] PAT 加密存储联调（写入/读取/删除凭据）

**验收**: 三平台账号添加并验证成功；重启后 PAT 可用；git 命令封装可执行并返回结构化结果

### M2 仓库与分支浏览 + 本地项目管理（8 天）
**仓库与分支（5 天）**
- [ ] 仓库列表页：分页拉取（含组织/群组仓库）、搜索、按平台/来源过滤、进入分支管理
- [ ] 分支列表页：分支名、最后提交、更新时间、保护标识；虚拟滚动
- [ ] API 错误统一分类与提示（认证失败 / 权限不足 / 限流 / 网络）

**本地项目管理（3 天）**
- [ ] 工作区配置：添加 / 移除根目录
- [ ] 多级异步扫描：识别子目录 Git 仓库（.git 检测）、扫描进度展示、深度可配置（默认 3 层）
- [ ] 本地项目列表：项目名、本地路径、remote URL；与平台仓库按 remote URL 自动匹配 + 手动关联
- [ ] 未关联仓库的创建阻断逻辑（提示"请先配置本地路径"）

**验收**: 任一账号（含组织/群组）仓库与分支数据与平台网页一致；fe 类多项目目录可全部识别并正确匹配

### M3 批量删除分支（4 天）
- [ ] 保护分支检测逻辑（三平台）；不可删置灰
- [ ] **保护分支识别失败时同样不可删**（置灰 + 提示"无法识别，请到平台网页确认"）
- [ ] 多选 + 二次确认弹窗（待删清单）
- [ ] 批量删除执行器（API 并发 ≤5、逐条结果、失败原因展示、可中断）
- [ ] 结果面板 + 刷新列表

**验收**: 删除流程符合安全设计；失败原因与平台返回一致；保护分支（含识别失败场景）无法删除；不依赖本地仓库

### M4 命名模板 + 批量本地创建（9 天）
**模板与向导（5 天）**
- [ ] 模板管理页：CRUD、多套模板、变量编辑（内置 + 自定义）
- [ ] 仓库级变量默认值：配置与一键套用
- [ ] 批量创建向导：选源分支 → 选模板 → 填参数 → 目标清单预览 → 冲突检测 → 执行 → 结果明细
- [ ] 冲突检测：本地同名分支标红阻止；**远程同名分支标黄提示（不阻止）**
- [ ] 分支名合法性校验（按平台规则）
- [ ] 单元测试：模板解析、变量替换、冲突策略

**本地 Git 创建流程（4 天）**
- [ ] 前置检查：仓库已关联本地路径（否则阻断提示）
- [ ] 未提交改动检测：阻断并提示用户自行处理
- [ ] 自动 fetch/pull 源分支（超时 + 进度 + 单条重试）
- [ ] 本地创建分支执行器：多源分支 × 多参数组逐条创建；**不执行 push**
- [ ] 结果明细（成功 / 失败 + git 原始报错）；完成后展示已创建分支清单（用户自行 push，无复制命令按钮）

**验收**: 未关联本地路径的仓库无法创建并被正确提示；有未提交改动时阻断；以模板 `{userName}/{projectName}_TG-{TG_ID}/{sourceBranch}` 为例，选 dev + sit 两源分支可在本地批量创建成功且不 push；本地同名阻止、远程同名提示生效

### M5 自动更新 + 打包（4 天）
- [ ] tauri-plugin-updater 集成；**免费自签名密钥**（tauri signer generate）生成与配置
- [ ] 更新检测（启动 + 手动）→ 下载（GitHub Releases）→ 校验 → 安装重启全流程
- [ ] GitHub Releases 托管更新文件；版本号管理
- [ ] Windows 安装包（NSIS/MSI）打包

**验收**: 旧版本可检测新版本并完成无感升级，无需卸载重装；自签名校验通过；无 Authenticode 证书（自用接受 SmartScreen 提示）

### M6 集成测试 + 修复 + 发布（5 天）
- [ ] 三平台真实账号回归测试（含私有仓库、组织/群组仓库、自建 GitLab）
- [ ] 本地创建场景测试：多级工作区扫描、未提交改动阻断、fetch 失败重试、monorepo 识别
- [ ] 异常场景：限流、断网、权限不足、证书错误、git 凭据缺失、并发删除冲突
- [ ] 性能测试：500+ 仓库、200+ 分支、50+ 本地项目扫描流畅度
- [ ] 安全审查：PAT 不落明文、日志脱敏、更新自签名校验、本地改动零破坏（不做 stash/reset）
- [ ] 发布 v1.0 安装包 + 用户使用说明

**验收**: 冒烟用例 100% 通过；v1.0 发布

## 3. 关键决策记录（已全部冻结）

| 决策项 | 结论 |
|---|---|
| 仓库范围 | 含组织 / 群组仓库 |
| 删除方式 | 平台 API，单仓库内多选，保护分支（含识别失败）不可删 |
| 创建方式 | 本地 Git：自动 fetch/pull → 本地建分支 → **不 push**（用户自行 push） |
| 无本地路径时 | 阻断提示，不 clone、不降级 API 创建 |
| 未提交改动 | 阻断并提示，工具不做 stash/reset |
| 冲突策略 | 本地同名标红阻止；远程同名标黄提示不阻止 |
| 应用名称 | Git Branch Manager |
| 更新方案 | GitHub Releases 托管；免费自签名密钥；不购买代码签名证书 |
| 扫描深度 | 默认 3 层，可配置 |
| push 辅助 | 无复制命令按钮 |

## 4. 风险与缓冲

| 风险 | 缓冲措施 |
|---|---|
| Gitee 保护分支接口与文档不符 | M2 期间提前实测；必要时在 M3 内调整 1~2 天 |
| 自建 GitLab 环境差异（证书/网络） | M1 即接入测试环境联调，避免后期返工 |
| 本地 Git 环境差异（凭据管理器、hooks、换行符） | M1 git 服务骨架即做可用性检测；M6 集中回归 |
| 用户本地仓库长期未更新导致 fetch 慢/失败 | fetch 超时 + 进度 + 单条重试；文档引导先手动同步 |
| 平台速率限制 | 适配器层内置退避重试；文档引导用户分批操作 |
| 需求变更 | 需求已冻结，变更走变更单评估工期影响 |
